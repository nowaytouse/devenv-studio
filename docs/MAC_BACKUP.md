# macOS / Windows 开发环境备份与配置

同一个Rust原生应用提供两端本机清单采集与配置审核。macOS可用Homebrew Bundle配置所选formula/cask；Windows使用既有可信开发工具与软件适配器。Windows系统设置在Mac上继续保持预览。

## 实际流程

1. 明确点击采集本机开发环境，读取标准位置工具提供的已安装包清单和版本。启动应用和打开页面不会自动采集。
2. 检查各来源的状态、包名及版本（Mac六类，Windows五类），搜索需要的条目。来源默认折叠并显示匹配数/总数，搜索自动展开有匹配的来源；展开列表按可视区域显示，不减少保存或迁移的条目。完整、未找到和失败分别记录，不能把失败解释成空环境。
3. 保存为新JSON备份。已有路径不会覆盖；取消或整体采集失败保留当前清单。载入其他备份时先完整校验，失败保留当前数据。
4. 保存/载入后，可进入现有迁移工作台审核Windows映射。报告按全部、已映射或其余说明过滤，每页20项；翻页和过滤保留勾选，合并包含整个报告内已勾选的可信请求。新分析初始没有勾选，软件、开发工具、电源和系统设置仍可一起保存和审核。

这是环境清单备份，不是磁盘镜像或完整环境副本。不复制工具二进制、源码项目、配置文件、SSH/API密钥、数据库、虚拟环境或包缓存；不自动安装、更新、上传备份或执行还原命令。已安装版本是观测证据，不保证未来能重新取得相同版本与构建。

## macOS来源范围

- Homebrew公式和cask分别采集所有已安装版本；不刷新tap、不更新仓库、不运行bundle安装。
- Cargo采集标准用户安装根的已安装crate及版本。
- uv采集已安装tool环境，不导出项目依赖或虚拟环境内容。
- NPM采集标准Homebrew Node与npm位置的全局顶层包；不导出项目node_modules、用户npmrc或认证。完整已保存的Mac清单可在环境配置页选包重部署，支持原版本或dist-tag；不还原包脚本、二进制或传递依赖锁定。
- VS Code采集标准稳定版应用列出的扩展与版本；不导出编辑器设置、账号或登录状态。

工具来自支持的标准路径，不从导入文件执行程序或参数。未支持的安装位置会显示未找到，不能据此断言软件没有安装。每条命令有输出、时间和取消上限；进程输出错误、非零或不完整内容不会成为完整清单。原始报错可能包含用户路径或私有内容，因此备份使用固定脱敏诊断，包名与版本也经过格式校验；自定义tap等不支持身份会明确标示遗漏。

## Windows来源范围

Windows采集Cargo、uv、NPM、Pip与VS Code五类，复用现有可信路径发现和严格解析器；不运行安装、升级、来源刷新或工具链引导。Pip只覆盖一个选定的已注册标准64位CPython解释器可见的发行包，不包括其他解释器、Conda、虚拟环境或可编辑项目。当前不采集Windows软件全集或WinGet安装清单。异常、缺失和失败分别记录，不保存原始路径或命令日志。

## 原生配置与清单交换

环境配置页提供7个Mac基础候选（Git、rustup、uv、Node.js、Python3.14、CMake、VS Code）与有效Mac备份中完整Homebrew来源的条目。Mac选择独立于Windows工作区，默认全部关闭。勾选后可审核、导出标准Brewfile，已有文件不覆盖。

在Mac执行需要已保存且内容未变的Mac清单、用户明确确认、可用Homebrew及本地运行时。载入的备份可以来自另一台Mac，不代表本机当前状态，也不是恢复点。执行重新生成私有临时Brewfile，仅含有效brew/cask身份；不执行外部编辑的Brewfile或任意Ruby内容。先bundle install --no-upgrade，再独立bundle check --no-upgrade；不运行cleanup、uninstall、force或zap。依赖可能改变或升级，取消和失败可能留下已执行部分，没有自动回滚；结果仅验证已安装存在，不验证历史版本、CLI或项目构建。执行前先在本地应用数据的environment-history私有运行目录重新采集并保存本机before.json（Homebrew两类必须完整），再保存并同步精确request.json；任一步失败都不运行变更命令；执行后另存脱敏result.json。只有started而没有结果的记录代表完成状态未知，不能当作成功或恢复点；结果持久化失败也不会报告成功。最近结果另可导出JSON，取消后后代安装器可能继续运行。Cargo、uv 与 VS Code 扩展已有独立 Mac 重部署流程；NPM 仍仅采集清单，不重部署。VS Code 只操作稳定版默认用户配置文件，不恢复编辑器设置、账号或同步状态；扩展身份与版本经 CLI 回读，但 Marketplace 后续版本、扩展行为和其他用户数据不受此清单保证。Cargo HEAD 仅来自固定审核仓库，并保存解析到的提交号；安装后 Cargo 清单只能回读包名和版本。

Windows继续使用原有可信方案流程，Windows备份按同提供程序精确身份匹配，未知项手动审核。WinGet清单导出只含当前Windows方案选中的软件与固定官方SourceDetails，不包含其他提供程序、版本锁、自定义来源或安装参数；完整跨工具档案仍使用应用档案。Windows执行保留现有LTSC版本门禁，不推断其他Windows版本兼容。

成熟GitHub项目的固定版本、许可证、实际接入与设计参考见ENVIRONMENT_SOURCES.md。

## 文件与迁移

原生备份schema1按platform固定来源集合，兼容原有Mac六来源文件，Windows五来源；记录采集时间、状态、包名、版本及范围警告。读取有1MiB、条目数、字符串、重复键/身份和版本限制，拒绝未知格式和符号链接文件。存储使用同目录临时文件及不覆盖式发布，不会覆盖既有备份。

Windows映射复用当前可信目录和固定来源，包含Homebrew产品映射、Cargo/uv/NPM身份和VS Code扩展。只有状态完整的来源参与；不完整或未知来源保持说明。版本不会拼入安装命令，不把Mac二进制或Homebrew依赖图当作Windows对等。OpenCV等映射保留Python绑定与完整SDK的差异。导入不改变Mac环境。

examples/mac-development-backup.json是合成示例，不是用户机器清单。真实备份应存仓库之外，并自行选择分享范围；应用没有上传入口。
